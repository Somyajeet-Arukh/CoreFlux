# Bounded resource control

`coreflux-policy` accepts a CoreFlux workload PID, one action (`affinity`, `nice` or `cgroup`), a bounded value, a duration of 1–30 seconds, a scorer decision file and an action log. It requires the latest decision to be CONTENTION or SEVERE. Without `--apply`, it records a dry run. With `--apply`, it records the previous state before intervening, applies the action, then restores state after the duration or a termination signal. It only accepts processes whose command name begins with `coreflux-work`. It checks the process identity before restoring, so a recycled PID is not changed.

Affinity pins each existing workload thread to one allowed CPU and restores each saved mask. A newly created thread is restored to the original leader mask. The nice action increases each thread's nice value by 1–10 and restores its prior value; applying it requires permission to restore priority. The cgroup action creates a temporary `coreflux-PID` group with a CPU quota of 10,000–90,000 microseconds per 100,000-microsecond period, moves the workload into it, then moves it back and removes the group. On this Docker Desktop host, cgroup migration requires `--cgroupns=host` as well as a privileged container. The controller setting is restored if CoreFlux enabled it.

The integration test checks a dry run, all three actions while the process is active, normal rollback, signal-triggered rollback and cleanup after the target exits. The policy is bounded to a specified workload and duration; it is not yet a continuously running closed-loop controller. Abrupt termination that cannot run cleanup, such as SIGKILL or host failure, requires operational recovery; the action log records the prior state for diagnosis.

`scripts/benchmark-policy.py` runs three paired trials with two one-thread CPU workloads sharing one CPU. The intervention moves the noisy workload to another allowed CPU while measuring the competing workload. The latest three pairs showed a median throughput improvement of 95.31%, with each pair between 95.06% and 96.08%. This is evidence for the defined isolation scenario, not a general performance claim. The full trial values are saved in `benchmarks/reports/policy-affinity.json`. The telemetry backend comparison is a separate experiment and does not broaden the resource-policy result.
